# Platform support

What browser features astryx-astro may rely on, and what happens where one is missing.

## The bar: Baseline newly available

A feature may be used **without a fallback** when [web-features](https://github.com/web-platform-dx/web-features)
gives it Baseline status `low` (newly available) or `high` (widely available): it works in the
current Chrome, Edge, Firefox and Safari, desktop and mobile. Such features are **Required**:
no feature detection, no polyfill, no second code path.

Anything else is an **Enhancement**. It must be either feature-detected (`@supports`, a check
in script) or harmless when unsupported (an attribute value or property the engine ignores),
and the tables below say what a user of an engine without it gets instead.

- **Pinned data.** Statuses come from `web-features`, pinned exactly in `package.json`
  (`devDependencies`): the newest release on or before 2026-10-25, **3.44.0**. A feature that
  becomes Baseline in a later release (for example scroll-driven animations, Baseline since
  2026-10-27 in 3.45.0) stays an Enhancement until the pin moves.
- **Partly Baseline features.** Where a feature as a whole is not Baseline but the parts used
  are, the entry lists those compat keys and only they are checked. CSS anchor positioning is
  the case in point: `position-visibility: anchors-visible / anchors-valid` keep the feature
  out of Baseline, while everything the layers use (`anchor-name`, `position-anchor`,
  `position-area`, `position-try-fallbacks` with flips, `@position-try`, `anchor()`,
  `anchor-size()`, `anchor-scope`) is Baseline. A newer option of an old feature is listed the
  same way (`focus({focusVisible})` under `focus-events`).
- **Server code.** Component frontmatter and the parts of `src/lib` shared with the server run
  on Node, whose floor is Astro 7's (`node >= 22.23.4`), not the browser bar. Node 22 has no
  `RegExp.escape` and no `Uint8Array` base64 (`fromBase64` / `toBase64`), so code that also
  runs on the server keeps its hand-written regex escapes (Chat pasted-text labels,
  ChatTokenizedText, the Markdown kit) and Calendar's base64 mask. Set methods, iterator
  helpers, `Map.groupBy`, `Promise.withResolvers` and `URL.canParse` are fine on both.
- **Testing.** The browser tests run in Chrome. Firefox and Safari support is argued from the
  web-features data, not exercised.

## Checking it

```sh
pnpm -F astryx-astro check:baseline        # node scripts/baseline.mjs
node packages/astryx-astro/scripts/baseline.mjs --write   # regenerate the tables below
```

`scripts/platform-features.json` is the list; the tables below are generated from it and the
pinned data. The check fails when a Required entry is not Baseline (or one of its listed keys
is not), when an id or key is unknown, when an Enhancement does not say how it degrades, when
the installed web-features is not the pinned version, or when these tables are stale. It
reports Enhancements that have become Baseline; promote one by deleting its detection or
fallback and changing its `use` to `required`.

When code starts to rely on another feature, add an entry. Moving the pin: set the exact
version, `pnpm install`, run the check, promote what it reports, `--write`.

## Platform checks that are not features

Some questions no feature detection answers. Each check lives in one place, with the reason:

- `elements/runtime/platform.ts` — every user-agent / platform read in the client code
  (ports of Astryx's own checks):
  - `isApplePlatform()`: macOS / iOS. Kbd shows ⌘ instead of Ctrl for `mod`, `hotkeys.ts`
    maps `mod` to Meta, and Slider ignores a Ctrl+click (a secondary click on a Mac). Reads
    `navigator.userAgentData.platform` (Enhancement `ua-client-hints`), else
    `navigator.platform`.
  - `isWebKitRenderer()`: Safari and every iOS browser. CodeBlock's range highlighting paints
    tokens with spans there instead of `::highlight()`, which WebKit paints unreliably inside
    code blocks (Astryx CodeBlock.tsx `isSafari`).
  - `isIOSDevice()`: iPhone / iPad / iPod user agents. ChatDictationButton plays no
    start / stop sounds there (Astryx useChatDictation.ts).
- The iOS focus-zoom floor: Safari on iOS zooms the page into a focused control whose text is
  under 16px. Field-composed text inputs, TextArea, FileInput, Typeahead, CommandPalette, the
  chat composer and the Selector, ComplexSelector and DateRangeInput triggers raise their text
  to 16px inside `@media (pointer: coarse) { @supports (-webkit-touch-callout: none) { … } }`,
  the same WebKit-only property test Astryx uses.

## Data notes

- `transition-behavior` and `focus-events` are Baseline as features; web-features 3.44.0 marks
  one of their compat keys unsupported in one browser (the `transition-behavior` longhand, the
  `preventScroll` focus option on Android). The check follows the feature status, as
  web-features does.
- `text-box`: the two longhands used (`text-box-trim`, `text-box-edge`) are Baseline per key
  since 2026-08-18, the feature as a whole is not; it stays an Enhancement for now.
